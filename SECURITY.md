# Reporting a security issue

Use this repository's **Security → Report a vulnerability** flow for suspected vulnerabilities or exposed credentials. Do not put passwords, tokens, private academy records, exploit payloads or sensitive screenshots into public issues, comments or pull requests. If private reporting is unavailable, use an existing private contact with the repository Owner rather than publishing the details.

Include the affected commit or deployment, expected and observed behavior, the relevant role/academy boundary and a minimal fictional reproduction. Do not test other people's accounts, tenants or connected services without authorization. Published source and synthetic test accounts do not grant permission to access a running service.

The project is under active synthetic-staging development. Passing tests, public source, a preview deployment or this policy do not establish a completed independent security review or a production-readiness guarantee. Deployment promotions remain Owner-controlled.

Repository maintainers follow the [public repository and CI policy](docs/00-governance/public-repository-and-ci-policy.md) and [secrets/access contract](docs/05-services/10-secrets-and-access.md).
