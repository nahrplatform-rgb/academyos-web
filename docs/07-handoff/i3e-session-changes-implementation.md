28 October2026. Moamen accepted the [policy](../06-delivery/i3e-session-changes-decisions.md) and separately approved the [connected design](../06-delivery/i3e-session-changes-design-contract.md) for implementation. Prior working approvals remain valid for their reviewed scope.

## Implemented behavior and boundaries

Current Academy Owner → Training → inspect a saved occurrence → Move, cancel and history → enter a reason and, for a move, new date/same-day times → authoritative before/after review → explicit confirmation → atomic persisted effective schedule, retained history, audit and operation receipt. The original `(program, occurrence day)` key remains unchanged. Other dates and the recurrence definition stay unchanged; a move outside the original period remains discoverable by effective date. Program occurrence pages retain original-key links; publication scope explicitly identifies original occurrences and shows each current date.

Trainer, capacity and the entire dated roster remain attached. An inactive assigned Trainer, occupied same-program destination, UTC person overlap, failed validation, stale schedule/plan/publication head, invalid DST time, started session or published date blocks a change. Published dates require the existing withdrawal first. Moved dates remain private until separately published. Canceled dates retain roster/history, cannot be planned or published and stop occupying active conflict slots. New whole-program planning/publication preparations exclude canceled occurrences; preparations captured before a change become stale. This is one-occurrence change only, with no reinstatement, makeup, fee, family visibility, attendance or notification rule added.

API `/api/session-changes` is staging-only, same-origin JSON, bounded8192 bytes, authenticated, fixed signed RPC, shared fail-closed60-read/10-write budget. Server SQL checks current Owner/academy/branch/setup and uses the existing academy lifecycle lock. Private tables have RLS and no client grants; no privileged client key or test authority path was added. Four `t9` RPCs expose minimal current state/review/save/original-operation reconciliation. Current read returns at most25 roster names plus25 history entries with sentinels; history is newest first with a scoped stable cursor. No per-date roster fan-out.

Individual planning now uses schedule-bound `q6_review_v2`/`q6_save_v2`, including before a first plan exists. Existing q6 operations/receipts remain available for reconciliation and internal publication validation. r7/s8 targets capture schedule revision as well as plan/head. Effective schedule reads and immutable publication projections keep original identity separate. Existing public RPCs still require the signed gateway; no direct client-table/helper permission was widened.

The product React remounts on account/academy/occurrence change, rechecks on focus, clears private state on denial, retains a reason through definitive failures and requires fresh review after state changes. Unknown save replies persist only the scoped operation ID and block replacements; reconciliation confirms the original or fences non-commit. A confirmed write followed by failed read offers a read retry. EN/AR native controls and shared workspace panes keep phone actions reachable.
