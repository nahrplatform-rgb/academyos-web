## Database integrity and lifecycle

Additive migration `20261028153040_i4c_attendance_correction_requests.sql`: three private deny-by-default RLS tables, bounded indexed reads and authenticated-only constrained RPCs; private helpers have no client EXECUTE. No account/member/recipient/mark seed. Existing attendance and lifecycle academy lock precedes each operation. Separate actor/operation IDs, payload fingerprints and fenced reconciliation prevent delayed replacement duplicates; actual SQL transactions—not client state—supply all-or-none outcomes. Expected row count and mark/version checks prevent zero-row approval.

An assignment authority revision changes on assignment updates, relevant invitation changes, membership authority changes and staff identity/membership changes. Request binds its original revision. Ending/suspending and restoring the appointment cannot revive the request. Ordinary lifecycle writers keep their established academy lock. Review additionally holds current requester membership/person/invitation/assignment rows, and the canonical mark, while checking eligibility. Raw administrative changes retain row-lock serialization/transaction failure rather than bypassing the epoch check; extended observed races remain separately tracked.

There is at most one currently valid pending request for a mark/version under the serialized authoritative operation; a second submit resolves it. A rejection does not prohibit a new eligible request. Original snapshots and decided requests/history are immutable. A changed mark makes a pending request stale. Deadline is server effective start through 24 hours after end, checked again at final commit. A request never extends it. Current Owner and different requester/reviewer accounts are mandatory. An Owner+Trainer account uses direct Owner correction.

## Retrieval, privacy and recovery

One academy/filter/current-session queue: 25 plus sentinel, stable created-at/id cursor; exact selected request/current mark; on-demand request history at most 20 plus sentinel. Present workflow creates one request and at most one decision history event per request; a larger future history is not assumed. Queue rows omit reasons, and byte-aware trimming keeps responses under 32 KiB. Private no-store reads revalidate on open/focus/reconnect/confirmed write; identity/academy/event/player remount aborts obsolete reads and clears drafts. Record/role navigation guards unsaved reasons; uncertain outcomes block replacement writes. Denied users can leave for their workspace without disclosing private content.

Recovery storage is versioned and subject/academy-scoped, storing only opaque operation/event UUIDs. No names, marks, roster or reasons enter browser storage. A lost request/decision reply is reconciled against the original actor-scoped operation. A confirmed result followed by failed reading permits read retry only. An uncommitted/fenced result retains an in-memory reason when available and requires a fresh review; reload intentionally cannot restore a private reason. Malformed transport success stays unknown until a correlated domain receipt is resolved.

The existing API enforces same staging origin, JSON shape, streamed 8 KiB request bound, current session and fail-closed external limits. Correction writes retain the existing signed gateway's 10/minute mutation budget; the attendance entry limiter is 60/minute. No budget was raised for this slice. Read budget is 60/minute. Server errors do not log reasons.
