One canonical mark per original occurrence/player; publication snapshot/event remains attached. Consequential mark, history, audit and correlated receipt commit atomically. Same operation/payload returns the original result; altered payload conflicts. Unknown result requires original lookup/fence before replacement. Client recovery stores only an opaque operation ID scoped by account/academy/event; no names/reasons/roster in persistent browser storage.

Current principal is resolved at every public function, including history/reconciliation. Trainer appointment, exact assignment, branch, publication and player eligibility are rechecked. No claimed role/actor or platform grant bypass. Tables have RLS and no ordinary-client grants; restricted public operations reuse the existing signed, rate-limited gateway. Attendance write/reconciliation uses a separate60/minute per-actor entry and signed-gateway budget to support roster capture; legacy mutation budgets remain10/minute. Both budgets fail closed on denial/timeout/outage, and no unreviewed endpoint gets the new budget.

Attendance protects training dates, plans, dated rosters, publication heads/events and published roster snapshots through table guards using the same academy lifecycle lock. This covers old q6/r7/s8/I3e writers and raw table changes under the guard. No historical delete/reinsert or weakening of prior assertions. Owner date detail and assigned Trainer schedule link to the register; protected dates show why changes are unavailable.
