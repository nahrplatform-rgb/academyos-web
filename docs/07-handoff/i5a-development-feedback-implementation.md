## Integrity, loading and recovery

One chain per original program/date/player with current event-bound authoring. Current assigned Trainer alone edits their own chain after effective session end; different-account current Owner reviews. Current assignment epoch is captured at submission; ended/re-enabled/changed authority cannot silently revive an old review. Owner can return it for a new current-authority submission. Published snapshot remains while a successor is reviewed; replacement head/history/audit/receipt are one transaction. Withdrawal clears family head without deleting historical records.

Expected versions protect drafts and review; identical operation keys replay minimal original results, changed payloads conflict. Unknown-operation lookup rechecks current access and fences an uncommitted key before replacement. Client validates matching receipt, blocks editing/context changes in flight, retains input for conflict/rejected writes and hides unconfirmed results after response loss. Confirmed-save/read-failure retries the read without another write. Private data clears on denial/account/player change; no local-storage draft or public cache.

Selected14-day session windows; session/queue/family pages20 plus sentinel, roster50 plus sentinel, history20 plus sentinel. Byte-aware page trimming prevents a fictional "complete" list when more data remains. Text≤2,000 characters/field, reason≤1,000, combined fields≤24KiB; stream and response≤32KiB. Entry and gateway remain10 writes/60 reads per actor/minute, fail closed on limiter failure. Budgets, actual measurements and limits remain separate.
