## Fix and regression sequence

| Finding | Required behavior | Planned cases |
|---|---|---|
| NR01 / NR04 / NR08 · Navigation | Use guarded client navigation for ordinary internal shortcuts. Retain external links, explicit retry, dirty/unknown guards and standard browser gestures. Distinguish document loads, route requests, prefetch and screen mounts in the trace. | WD-58, WD-68 |
| NR02 / NR03 · Return | Pair focus/visibility/online signals, run a scoped check only when needed and preserve permitted same-scope results and task context during the wait. Keep structural context when an authority check requires masking and clear incompatible private data on denial or scope change. | WD-61, WD-66, WD-69 |
| NR03 / NR07 / NR14 · Clicks and queries | Covered local controls make zero operating requests. A changed query needing the server loads in its own panel. Keep the old and new query scopes distinct, and prevent an obsolete response from replacing the latest view. | WD-60, WD-62, WD-70 |
| NR03 / NR05 / NR07 / NR16 · Saves | Keep the task in place through a held write and follow-up read. Use the verified receipt for affected rows/counts where sufficient, otherwise read the smallest authoritative scope. Keep confirmed save plus read failure distinct from unknown write. Preserve original identity, atomicity and authority. | WD-63, WD-65, WD-71 |

Use deliberate held responses for regression assertions. Capture the document count, operating API starts, visible state before/during/after and focus/scroll/selection/dirty state. Count Next route/prefetch and identity requests separately. An operating API read can invoke auth, rate controls and a scoped database call. Current end-to-end latency and provider cost require a measured profile. [Example API boundary](../../apps/web/src/app/api/experience/route.ts#L15) · [Service-impact register](../04-engineering/request-service-impact.md).
