## Real source and boundaries

`qr-workspace.tsx`, `qr-camera.tsx`, `qr-print-card.tsx`, `lib/qr-attendance.ts`, `/api/qr` and three protected routes connect current Clerk identity through the existing signed request gateway to eight constrained q13 RPCs. Shared shell/panes/controls and existing player/program/Trainer/attendance navigation are reused. Camera permission is requested only after Start; streams stop when leaving/hidden/context changes. Pending capture pauses the existing stream; a stationary card stays latched until removed. Frames stay on-device. Native QR detection is used when available; pinned jsqr1.4.0 is the local fallback. Pinned qrcode1.5.4 creates real private in-memory printable SVGs; @types/qrcode1.5.6 is development-only. No remote image optimizer or public card URL.

Cards use32 cryptographically random browser bytes and strict versioned base64url syntax. Only SHA256 hashes persist; raw codes are never stored in receipts, sessionStorage or audit. Reload cannot redisplay a lost issued code: explicitly replace it. SessionStorage holds only subject/academy-scoped opaque operation identifiers. Reconciliation checks the original operation and fences uncommitted work; it never retries a replacement blindly. Confirmed-write/read failure offers read recovery. Recovery from another QR view returns to the original card/settings/scanner context. Current denial clears private names and scan data.

Migration **20261028184008_i4d_qr_attendance.sql** introduces five private RLS/no-client-grant tables and one published branch/time lookup index; all public RPCs are authenticated-only, with empty search paths,3s statements and2s lock timeouts; private helpers have no client execute. Current actor, branch, assignment, publication, player, roster, credential and scan window are checked server-side. Canonical attendance/history/receipts/audit commit atomically. Existing academy/operation locks and optimistic card/settings versions serialize conflicting writes; final server-time validation rolls back a window that closes during capture. Shared player eligibility is reused by manual recording without changing manual timing or correction authority.

## Retrieval, speed and cost bounds

Session pages are25 plus sentinel; responses are trimmed below24KiB. Matching uses the complete explicit selected scope, maximum25: oversized match results require narrowing and never silently become unique. Requests are8KiB maximum. API entry/read budgets are60/minute; capture/reconciliation shares the existing60/minute manual attendance write budget. Owner card/settings mutations retain the general10/minute gateway budget. Dependencies fail closed. No global limit was raised. HTTP has15s timeout and no-store/referrer protection. No background scan polling, saved frames, image upload or added paid service.

Targets: warm SQL reads p95 below300ms; match/commit HTTP p95 below1s on declared stable test network; local decode p95 below50ms at the declared frame size; bounded response below32KiB; no duplicate canonical marks/history. Only local SQL/decoder targets are measured here. [Actual production chunks](evidence/i4d-local-2026-10-28/bundle.json) total62,593 gzip bytes for the two QR-containing lazy chunks, below80KiB. This does not measure total route JS or physical camera startup. HTTP/burst fairness, cost/WAL, real print readability and physical device proof remain open.
