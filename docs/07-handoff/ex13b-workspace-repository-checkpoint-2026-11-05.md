| [Local repository](../../apps/web/src/lib/local-workspace-repository.ts) | IndexedDB stores non-extractable browser keys and authenticated ciphertext in a separate database. A transaction saves each page and its checkpoint together. The completed head changes only after rechecking the encrypted pages from seed to root. Readers retain the previous complete generation while staging runs. |
| Replacement and retention | A newer completed Calendar window removes older overlapping windows in the same commit. A revision fence refuses late older completion. Matching manifests can renew freshness without downloading pages. A key response cannot extend coverage. Opening the namespace sweeps expired copies. Retirement drops the key and fences tabs before deleting ciphertext, including retry after interrupted cleanup. |

The repository can read 12 encrypted pages per search slice and return a continuation. This first mechanism avoids clear-text name indexes. A local search for one match in the 1,000-player fixture scanned all 40 pages in four slices and used zero operating requests. A scoped unchanged manifest used one request and zero pages. These observations are from loopback and Chromium. Cold startup, foreground responsiveness and storage headroom still need measurement before selecting the final search path. The test does not cover mobile Safari, OS eviction or a live academy dataset. Strict storage durability and browser key support must be checked when choosing the real runtime fallback. The browser API provides transaction durability hints, so the repository checks the selected setting before writing. [IndexedDB transaction options](https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/transaction)

The 18 checks exercise both real Next handlers, actual SDK and gateway signatures, disposable PostgreSQL and Chromium WebCrypto/IndexedDB. They include wrong actor, wrong key root, key reuse, namespace refusal, row tampering, a failed page/checkpoint transaction, concurrent tabs, browser process restart, unchanged verification, stale Calendar overlap, missing ciphertext and cleanup failure. Clerk, Redis and the PostgREST wire use fixtures. The restart test reloads the fixture code from loopback before opening IndexedDB. Normal-route offline startup is a separate acceptance case.
