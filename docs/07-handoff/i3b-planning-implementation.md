Platform-only, Manager, Trainer, Guardian and Player do not gain draft-planning authority.

Each save serializes on the existing per-academy Trainer lifecycle lock before current Owner/setup/target/Trainer locks. This intentionally bounds concurrency within one academy and avoids cross-date overlap write skew and save/end lock inversion; it is not an aggregate-throughput guarantee. Current version, selected people/branch, eligibility, roster count, capacity and overlaps are rechecked at commit. Capacity/Trainer replacement/roster deltas/operation result/audit commit atomically. Stored count is checked against actual roster rows before update. Current Trainer eligibility is projected on read, so ending an appointment preserves its planning reference but shows unavailable coverage. No reactivation or grant is seeded.

Private operation payloads retain ID-based intent/version history without names/contacts in audit or telemetry. Same committed operation/same payload returns its original minimal result; changed payload conflicts. Unknown replies reconcile that original operation or serialize a cancellation fence. Confirmed save followed by failed reread stays confirmed and retries only the read. Reload retains only the scoped opaque operation ID, not unsaved private form fields. A canceled operation after reload explicitly requires re-entry of lost choices.
