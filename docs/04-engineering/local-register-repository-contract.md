## Scope, reuse and boundaries

- Extend the tested automatic-key mechanism into a domain-specific TypeScript adapter; share crypto primitives with the research harness. Use native IndexedDB: existing dependencies already supply browser tests/bundling; no new wrapper or second persistence framework is justified for this bounded slice.
- No current route/component imports the repository. No network calls or automatic database opening on module import. The caller must later supply a current verified account/academy/Owner/device/field-epoch binding from a reviewed authority. Local partition labels alone are not authority.
- Bind authenticated encryption to schema, full scope, purpose and record identity. Separate read keys/replicas from device-plus-server-wrapped pending data. Logout/30-day cleanup removes reads/cached recovery material, durably fences old work and retains original pending ciphertext. Missing/corrupt keys or metadata never reset the database.
- Reuse `attendanceRequest` for exact immutable register packets and `isRegisterReceipt` plus exact original selected count for settlement. No generic offline queue, correction, grant, timestamp winner, fake global roster revision or cancelling `reconcile` retry.

## Stored contract and transaction rules

Read fields are the existing minimal `AttendanceRoster` projection and player ID/name/current mark/version. Roster rows are encrypted separately, indexed by opaque scope/event/generation/player ID, with bounded 50-row local queries. IDs/index metadata still reveal linkage; private field/index approval remains required before enablement.

A paged import stages encrypted rows and checkpoint together, retains prior complete data, and switches the active generation only after exact count/saved/order/header/coverage checks. Legacy pages have no MVCC snapshot receipt: their completeness means all bounded rows transferred, **not globally simultaneous versions**; legacy imports explicitly report `coherence: per-row-only`. The later [EX-04 versioned contract](register-download-contract.md) stages even the final page until server completion and actual disk re-hash; that distinct path reports `verified-transfer`. Server per-row write checks remain authoritative; neither path is privately enabled. Interrupted imports can resume using their stored transfer ID/cursor; unknown, empty, incomplete and complete are distinct. A local command transition invalidates older in-progress imports so a late pre-save page cannot reactivate a stale basis.

Capture validates a complete, open basis and only unmarked version-zero selected players, then atomically stores the immutable original JSON, selected-row local overlay and pending identity. Acknowledgement waits for transaction completion. One unsettled original per event blocks replacement across tabs; other events are independent. Original packet ≤1000 marks/131072 UTF-8 bytes, matching the existing endpoint. Protected local display data is separately bounded; no truncation.

Before handing out an original for dispatch, persist Unknown. Reopen/retry returns its exact packet/ID/time. Definitive refusal retains Needs review; transport loss remains Unknown. Receipt validation and settlement are atomic. A count-only receipt proves the original saved; it does not prove today's roster/aggregate. Invalidate the basis for a current read without losing the confirmed receipt when that read fails. No automatic retries or transport are in this adapter.

Use compare-and-swap revisions and durable cleanup/activation fences; old handles/late crypto cannot return private values after disposal or cleanup. The first activation reserves its fence before key delivery. Cleanup is two-phase: persist Cleaning, then delete read material. An aborted deletion stays blocked across restart until cleanup finishes. This is not a claim of physical secure erasure. Writes request and verify [strict transaction durability](https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/transaction); unsupported modes fail closed. This is not a power-loss, browser-eviction or backup guarantee. Unsupported/newer schema, version-change, blocked storage and corruption fail closed without deletion. Original discovery and local roster queries return at most50 entries plus continuation. Recovery verifies one retained envelope under the fixed recovery-key ID; rotation is refused, not silently attempted.
