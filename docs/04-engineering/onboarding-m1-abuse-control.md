# M1 direct API abuse-control change packet — 23 October 2026

Authorized by Moamen's “do all” follow-up to SEC-M1-ENG-002. Scope: synthetic staging, J02–J04 authentication/context/admission/invitation/setup/recovery actions; AO-004/008/169/175/178. Accepted M1 business policy is unchanged. This is an engineering control, not a commercial quota, privileged grant, independent audit or final acceptance.

## Boundary and connected behavior

Today the app checks Redis but a caller with its own valid JWT can reach the public RPCs directly. Require a server-only, short-lived HMAC gateway attestation in the existing private `verified_subject` helper. It binds the current JWT subject, actual PostgREST method and RPC path; purpose is domain-separated from recipient/delivery proofs. All ten authenticated entry points (eight M1 and two legacy identity/membership functions) already reach this helper, including nested calls. Keep current role/tenant checks, private-table grants, RLS, transaction/lock/time bounds and receipts. Anonymous delivery retains its separate signed worker protocol.

The shared server database transport spends the existing 60 read / 10 write requests per actor per minute before signing or sending a user RPC. Invitation acceptance is a write; review is a read. Legacy bootstrap is a write. Denied and failed RPC attempts consume the external Redis budget, even when the database rolls back. Replays still use the original operation ID and budget; a lost response is reconciled after the budget recovers. Existing EN/AR limited/unavailable/refresh states apply; no new screen or business rule.

Public invitation exchange gets a 30/minute network-source budget and 300/minute staging-wide budget before cookie encryption. On Vercel use its overwritten `x-vercel-forwarded-for` only, validate a single IP, HMAC it with a domain-separated server key, and fail closed if missing/invalid. Local development uses one fixed local bucket and ignores supplied IP headers. No IP, proof, JWT, token or private payload is logged/stored in business rows. Redis keeps short-lived pseudonymous counters with analytics disabled, no retries and existing deadlines. These controls bound expensive downstream work; they do not make internet request volume or Redis billing universally bounded, nor replace provider network/DDoS protection. Shared networks can share the exchange budget; keep it independently tunable through a reviewed change.

Proofs never enter browser responses or cookies. Captured server-to-database attestations would be replayable within their 30-second lifetime for the same subject/path/method; they are not body signatures, membership assertions or reusable browser credentials. TLS, server-only key custody and no header logging remain required. Current database authorization still validates each actual operation, including membership revocation. No service-role app client, public helper grant, schema exposure or provider subscription is added.

Rejected: transaction-local counters, because failed/rolled-back requests erase them; unbounded direct RPC access, because it bypasses Redis; privileged service-role replacement, because it would discard caller authority. A platform pre-request hook is unnecessary because every current authenticated entry point already shares the helper. New public functions must use it and be covered by the entry-point inventory test. Storage/Realtime do not inherit this control; existing private/denied access stays unchanged.

## Verification and rollout

Add negative tests for absent/forged/expired/future/wrong-subject/wrong-path/wrong-method/recipient-purpose attestations, all exposed caller RPC entry points and missing PostgREST metadata. Run the original SQL permission/replay/concurrency/interruption tests with valid transport attestations, not privileged bypasses. Unit-test limiter denial/timeout prevents signing and network calls, classification (especially invitation review/accept), no header forwarding to another origin, and network-key spoof/missing cases. Retain existing UI and business assertions.

Deploy the signed transport app first (compatible with the old DB); confirm the canonical staging alias and signed-in read/replay. Then apply the additive helper replacement, preserving function ownership/ACLs and business rows. Verify hosted direct REST calls without a proof fail, normal app requests work, cross-academy denials persist, and pre/post aggregates match. Reload the schema cache. Do not roll back to an unsigned app after enforcement. If app trouble occurs, forward-repair while denying writes and retaining original operation IDs; removing the gate needs an explicit reviewed migration, not an environment bypass. No destructive data migration or new privileged provisioning.

Status: implemented locally. All 16 disposable PostgreSQL groups and 31 app tests pass; lint, typecheck, production build, both actual React UI modes and five production-server E2E checks pass. The entry-point inventory explicitly preserves the separately worker-signed delivery RPC. The actual Supabase SDK test verifies limiter denial remains an HTTP 429-capable gateway error rather than being swallowed as an empty result. Hosted apply/deployment/verification are pending. A temporary provider-connector transport outage interrupted live metadata/advisor reads; one metadata read and the canonical alias later succeeded. No hosted mutation has been made for this fix yet. Independent human/security review and physical-device/full-load/owner acceptance remain separate gates under the engineering charter.
