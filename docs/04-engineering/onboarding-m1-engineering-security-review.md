## SEC-M1-ENG-002 — app throttles do not bound direct authenticated RPC traffic

Status: open resource-abuse/cost control gap; source-confirmed scope, not a newly demonstrated hosted attack or permission bypass. The onboarding API applies Redis limits, while the authenticated role intentionally has EXECUTE on the narrow M1 RPCs. Those database operations enforce current permissions, input/result bounds and locks, but do not implement the app's per-actor request-rate budget. Therefore an authorized caller using the Data API directly does not traverse that Redis check. Public handoff exchange also precedes identity/actor throttling; its body and cryptographic work are bounded, but an edge/IP abuse budget was not independently verified.

Do not describe the app's 10 writes/60 reads per minute as a complete database-wide abuse boundary. Existing direct table denial, tenant/role checks and restored execution limits are still necessary and separate. No hostile traffic was generated against staging to prove exhaustion. Before a broader pilot, specify and test a consistent direct-RPC/edge abuse strategy with correct replay/unknown-outcome behavior and measured cost; do not introduce a privileged app client, weaken current authorization or silently invent commercial quotas. No policy or implementation change for this open gap in this review.
