## Trust crossings and invariants

Clerk verified identity → staging-only same-origin API → signed, allowlisted gateway with current actor budget → authenticated public RPC → private academy tables/current memberships → separate approved-link family projection. Current active Owner reviews a different account's submission; current assigned Trainer authors only that exact ended published rostered session. A current assignment does not transfer another author's chain. A restored assignment must resubmit under its new authority revision before publication. Earlier valid publications persist independently of Trainer access, while current link/opt-in and withdrawal still control family reads.

Sensitive classes: family-visible narrative, private staff note, internal review/withdrawal reasons and actor references. Family SQL selects an explicit publication projection without private fields, requester/reviewer identity, other players or draft history. Staff and Guardian routes call the same signed gateway but separate domain RPCs. Possessing an assessment/event/link UUID does not confer access. No new login/account, service-key caller, email, export or external side effect is introduced.

## Prevention, detection, containment and recovery

- All six new tables have RLS enabled and no ordinary/public direct grants. Internal helpers are not executable by application roles. Public functions revoke PUBLIC/anon execution; bounded authenticated RPCs verify the existing gateway proof and current domain scope. Definer wrappers have empty search_path and3s statement/2s lock limits. Current actor/assignment checks are enforced in SQL, not by buttons.
- Lifecycle locks use existing Guardian→Trainer ordering; consequential writes take actor-bound operation locks and expected versions. Submission freezes exact text; publication, head, immutable history, safe audit and receipt commit atomically. Current assignment epoch is checked again at publication. Immutable submissions/publications/history reject update/delete. No historical score reinterpretation: narrative-v1 context persists.
- Idempotency stores payload fingerprints; same key/different payload conflicts. Unknown-operation lookup checks current scope before returning minimal original results or creating a durable cancellation fence. The UI validates a matching receipt, blocks duplicate submission/context changes while pending, retains rejected text and reconciles response loss before replacement.
- Exact fields/UUIDs/versions/language/reasons are validated at API and database boundaries. Request stream≤32KiB, text fields≤2,000 characters each, reasons≤1,000 and combined text≤24KiB. Response≤32KiB. Direct SQL predicates and bounded cursor lists protect alternate callers; shared gateway limits remain10 writes/60 reads per actor/minute, with corresponding entry budgets. No limiter increase.
- Structured audit stores action, assessment/version/revision/operation references without narrative/reason text. Internal history separately retains reasons and submitted text under current staff authority. Do not enable broader telemetry or log provider messages/payloads.
- Guardian development opt-in defaults absent/false. Existing training opt-ins do not expand. Revocation/withdrawal clears the next authorized UI read, including resume; unsaved drafts stay in memory only. Family lists/details read the current publication head. No public caching/local-storage persistence.

## Required adversarial proof and limits

Disposable PG17 tests exercise exact author/reviewer flow, private-field exclusion, no implicit opt-in, foreign academy/role/revoked access, receipt fencing, concurrent versions/decisions, assignment epochs, rollback at each consequential table and immutable history. Actual API tests use synthetic provider adapters for origin, body/field rejection and fail-closed limiter ordering. Actual React tests use synthetic identity/HTTP adapters for visible flows, denied clearing, EN/AR/mobile navigation and lost-response recovery. These layers are not interchangeable with hosted JWT/HTTP proof.

Remaining before a full release claim: independently reviewed security/privacy, extended hosted direct-API/current-claim/race checks, physical-device/screen-reader/keyboard breadth, stable-network HTTP p95/bursts and WAL/storage/cost. No critical discovered boundary failure may be waived by design approval. Current local results, hosted migration/app and working usability acceptance are recorded separately in the implementation receipt.

## Rollout and repair

Additive migration only; no existing domain row, account or opt-in is seeded. Before hosted apply: trusted encrypted backup, isolated restore with this migration, preexisting domain fingerprints and current advisor baseline. After apply: migration inventory, RLS/grants/timeouts, zero enabled development links, unchanged prior fingerprints and advisors. Application rollback hides new entry points; do not delete historical submissions/publications to roll back. A failed schema transaction rolls back; a discovered contract defect requires forward repair while keeping private grants closed. Any test access restoration must have fresh explicit authorization and a prepared ending transaction.
