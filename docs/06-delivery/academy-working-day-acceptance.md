## Why this gate exists

The pilot must establish that the operator can finish useful work and keep their place throughout a working visit. Request reduction, source snapshots, a deployed dark theme or isolated quick screen recordings are supporting evidence; none alone establishes a usable working day.

The first bounded live pilot is the **existing Academy Owner experience**, with implemented Home, Calendar/program/date planning, People, attendance and permitted reviews. Trainer/Guardian behaviour is tested through their existing separate contracts and authorized identities as adoption reaches them. Manager/Player operational portals, fees, messaging, media and other unbuilt work are retained future scope, not simulated completion or mandatory nonexistent pilot tasks.

EX-11 has two checkpoints: an Owner pilot acceptance checkpoint, then repeated role/journey adoption checks. Record the exact accepted subset. Do not mark the whole stage, all findings or all roles complete from the first checkpoint.

## Measurement protocol

Every run declares:

- Source commit, migration/contract versions, actual deployment/alias and configuration boundary; local versus hosted versus physical device.
- Persona/current permitted capability, fixture sizes and record states; no real children, credentials, private token/header/HAR/body capture or unnecessary personal screenshots.
- Browser/version, viewport, device/CPU profile, network round-trip/bandwidth/loss, region, active-tab state and concurrent workload. Emulation is not a physical-device test.
- Cold state: fresh relevant navigation/data state versus a new authentication session; distinguish them. Warm state: exact already-visited resource/query and the accepted freshness/eviction configuration. Do not silently change cache state between samples.
- Task start and **semantic completion**: useful content and required action available. Next route announcer, title, skeleton or old row is not completion. Include failed/time-out attempts and declare sample size.
- Before/after comparable runs: same role/data/state/profile and timings. Avoid comparing one delayed local fixture to an undelayed hosted browser and calling it a speed improvement.

Report separately:

| Measure | Existing target or required criterion | Evidence limit |
|---|---|---|
| First useful Home/roster/task | p75≤3s on the declared representative profile, including required identity/context | A shell paint is not a task. One sample cannot establish p75. |
| Local interaction feedback | p75≤200ms for selection/click/pending acknowledgement | Acknowledgement is not confirmed commit; do not fake Saved to meet the target. |
| Ordinary authorized reads | p95<800ms under the declared server/network/workload interpretation | State included layers. Local SQL time is not end-to-end API time; count failures/timeouts. |
| Layout stability | CLS≤0.1 on the declared journey/profile, plus stable control/focus/return checks | Passing CLS does not prove no scroll clamp, keyboard issue or RTL truncation. |
| Warm return | Preserve allowed context; no avoidable document reload, duplicate read or page-wide blanking for independent work | If private reuse is unaccepted, current-authority wait remains explicit. Do not report instant private reuse. Set any new numerical warm-read target through the reviewed pilot contract. |
| Request ownership | Named budgets for cold/warm/return/focus/save/preparation; no unexplained identical in-flight work | A cache/timeout/cancel counter alone does not prove saved backend work. |
| Resource cost | Requests, bytes, speculative work used/wasted, query rows/time, limiter amplification and available provider meters | Distinguish measured, modeled and unavailable; no blanket50% cost reduction from one removed app request. |
| Task continuity | No unaccepted lost input, scope leak, duplicate operating action or misleading state; record clicks/errors/assistance | Existing scoped tests support cases but do not establish full working-day usability. |

The existing targets are planning/acceptance targets, not newly claimed current measurements. Record actual distribution and profile. Do not add an analytics service, persistent user tracking, session replay or sampling policy to gather them without the appropriate separate decision. Controlled local instrumentation and sanitized staging observations can establish bounded facts.

## Required new measurement and recovery profiles

1. **First preparation:** cleared/new store; authenticate and task-first essentials; track every finite page/completion check and user-interactive preemption. No hidden full-data barrier for unrelated work.
2. **Normal reopened store:** restart app/tab with compatible persisted records and accepted local access. Measure key/unlock/store open/index query versus current identity/manifest calls separately. An unchanged complete dataset must not transfer its pages again; zero pages does not mean zero auth/network calls.
3. **Changed data:** sparse upserts/deletions, moved/withdrawn date, field-scope epoch and same-timestamp race. Validate atomic rows+watermark, no ghost/private rows, preserved draft basis and actual counts. A replacement implementation reports full replacement bytes honestly.
4. **Interrupted preparation:** pause after page1, reload, resume under same snapshot; expired/moving snapshot rebases only the affected generation and preserves prior valid data. Complete-empty versus unknown page is explicit.
5. **Actual storage/browser failure:** quota/private mode/eviction, wrong/missing key/corruption, blocked migration/old tab/downgrade. A failed local transaction never claims saved or complete; unresolved operations retain their original discovery fence.
6. **Device and access:** same/different account, two academies, branch/role/child changes, trusted versus shared device, known denial and offline lease expiry/clock rollback. No instant disconnected revocation promise; no lease extension on reopen.
7. **Connectivity and launch:** public shell/deep link plus private unlock before claiming actual offline cold start; mocked failed fetch is insufficient. Background sync while active and after suspension/reconnect has separate evidence; closed-app execution is not guaranteed.
8. **Save integrity:** current server-confirmed command/review/receipt rules unchanged. Read-only local support cannot approve an offline mark/payment/publication. Any future local acknowledgement/outbox is tested under its separate domain policy.

The dataset profile includes more than one directory/month page as well as18-player/40-date tasks. Prove local covered-scope search and indexed visible-range reads without dumping all disk records into memory. Existing latency/CLS targets remain, with cold local-open versus current HTTP and device-specific privacy costs disclosed. No native→web timing extrapolation or fabricated service saving.
