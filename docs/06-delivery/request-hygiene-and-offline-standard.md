# Request Hygiene, Responsive Loading and Explicit Offline Support

31 October2026. Linked addendum to [the original app implementation plan](app-implementation-plan.md), based on [confirmed findings](../04-engineering/request-findings-register.md) and [service/cost analysis](../04-engineering/request-service-impact.md). Applies to upcoming work across I0–I10 and the incomplete Charcoal redesign. It changes no product behavior or historical approval.

## Authority and status

Existing charter rules remain mandatory: current server authority, tenant/field isolation, bounded retrieval, atomic/idempotent consequential saves, original-operation reconciliation, honest state, and separate design/local/hosted/deployed/Owner/security gates. This addendum makes review/evidence requirements concrete. Cache TTLs, retained private stale display, persistent private drafts, offline queues, retention and monitoring sampling below are **recommendations**, not accepted business/privacy policy. No implementation or dependency migration is authorized by this analysis alone.

Do not weaken signed preview chains, whole-program atomicity, publication snapshots, attendance correction deadlines, recipient verification, card revocation or active relationship checks to improve speed. Existing data and prior functional acceptance survive the redesign. “Offline-first” is not an appropriate blanket promise for a role-scoped app; each capability must declare exactly what works disconnected.

## Architectural ownership

| Layer | Responsibility | Must not do |
|---|---|---|
| Shared shell / router | Stable navigation, identity-loading geometry, accessible focus/scroll and destination context; guard dirty/unknown exits | Treat a displayed role, menu or cached membership as authority; force all internal transitions to document loads |
| Domain projection owner | One scoped owner for each resource/query; query key, in-flight read coordination, cancellation/generation, display state, pagination, invalidation | Duplicate same projection independently in panels; run global automatic retries; combine incompatible Guardian/Trainer/Owner projections |
| API route | Body/origin/rate checks, caller session, operation contract, safe response/error/timing | Trust client role/branch/link, log private payloads or weaken outer protection because inner protection exists |
| Signed gateway | RPC whitelist/current caller proof, bounded transport, fail-closed inner limiter | Become a public shared cache or a privileged-key shortcut |
| Database operation | Current membership/relationship/version, exact scope/projection, atomic commit, immutable audit and idempotency | Authorize from stale client state; replace authoritative count with loaded page length |
| Background job | Durable explicit side effects and retries under job identity | Send mail or query provider billing per Home render |
| Browser persistence | Reviewed preferences/navigation/opaque recovery references; explicit private-store contract only after policy | Store tokens, player rosters, full feedback or drafts by default; promise remote deletion of disconnected data |

Suggested read key: environment + subject + academy + capability/role + branch/link + resource + projection version + normalized filter/date/cursor + locale/timezone if representation changes. Role string is partitioning only; server still resolves authority. Clear incompatible results and ignore late replies on subject/academy/role/branch/link change or denial. Bounded cardinality and eviction prevent query-key leaks. Do not place caller-bound RPC results in shared Next/CDN/ISR caches.

### Read coordination and loading

1. Inventory critical, deferred and on-demand projections before build. Declare cold/warm and selected-detail request budgets from actual contracts. Parallelize independent reads only. Receipt/context dependencies remain sequential.
2. One identical in-flight read per exact permitted key. Define ownership/refcounts so unmounting one subscriber does not cancel another's read. Scope changes abort obsolete work and invalidate generations; caller abort does not prove backend cancellation.
3. Resume events are a coordinated burst, not independent focus/visibility/online commands. Test synchronous and40ms-separated events and events during an in-flight read. Revalidate promptly; no arbitrary multi-second throttle concealing revocation. “Once per burst” needs a documented transition/in-flight rule, not an unsupported timing constant.
4. Separate initial access, same-scope revalidation, changed query, unavailable, stale and denied. Keep nonprivate shell and layout stable. Retain typed input and safe selected ID; redisplay selected details only if the new projection permits them. Expired authorization clears private content; failure is not empty or zero.
5. Keep operation reconciliation distinct from refresh. Unknown outcome blocks replacement, even if network comes back. Preserve validated opaque operation identity across supported reload/crash paths; feedback text is not required in that recovery locator.
6. No page-wide spinner for independent panel refresh. Panel error must leave unrelated authorized tasks usable. Show as-of/refreshing when meaningful. Preserve EN/AR focus, list/scroll and accessible announcements; do not reset task on a tab return.
7. Local presentation controls (language and loaded-page search) must remain usable during rereads without restoring private rows, making operating requests, or adding hash/history navigation. Keep input identity/focus during the check. Busy/unknown locks still fence route changes and operating commands; a local locale change must not replay or replace an operation. Test with held responses rather than assuming a quick local read proves continuity.
8. Do not reuse approval/preview just because typed fields survived: duplicate review, signed date checks and stale expected versions must be refreshed under their exact contract.

## Offline and local-data decisions still required

Default remains online-only for operating reads/writes, with honest disconnected state and retained current in-memory editing where safe. Public static assets and nonprivate preferences can be local; read-only stale private views, private offline drafts and write queues are **not authorized by this document**. Proposed text retention requires explicit duration/size, shared-device warning, sign-out/purge and upgrade behavior. An opaque operation locator may contain identifiers but no private draft; keep it private/scoped and reconcile against current permission.

If a future capability gets an explicit offline write policy: assign durable operation identity at intent creation; retain expected versions and ordered dependencies; bound queue bytes/items and expiry; encrypt only as defense in depth; revalidate account/academy/role/link and current recording window on sync; send each canonical idempotent command once and query original outcome after uncertainty; stop dependent commands on conflict/expiry/denial; show user conflict review rather than last-write-wins; purge disallowed unsent intent without deleting immutable server history. No automatic payment/access grant/publication/ownership/QR validity queue. Attendance offline remains separately governed by D-011/D-012, not accepted by generic cache approval. Queue ordering, background expiry, multi-tab/device concurrency and local retention need decisions before building. A disconnected device cannot be remotely erased or immediately informed of revoked access.

## Prioritized fix implementation handoff

This is copy-ready execution scope for a separately authorized fix task; analysis did not implement it.

1. **P0 baseline and navigation (1–2 engineering days).** Recheck tree/source/deployment; fix NR01 only on safe internal destinations. Test real Next production router, modifier/new-tab clicks, native Back/Forward, dirty cancel, busy and unknown fences, locale/academy allowlists. Acceptance: H1/H3/H4 no document transitions; intentional identity/terminal reloads remain explicit.
2. **P0 scoped read coordinator and recovery (2–4d +1–3d recovery).** Pilot Experience then Development opaque recovery reference; review NR17 storage-failure guarantees per operation. One identical in-flight owner; test synchronous/separated focus, online and pending read/writes; reproduce crash unknown and resolve original identity. No private payload persistence. Acceptance: no duplicate starts for the declared resume transition, no leaked cross-scope late response, no replacement of unknown commands.
3. **P1 task continuity (2–4d).** Separate initial/revalidate/query-change states; retain geometry, filters, safe selected ID/scroll/focus. Decide stale-private display before retaining private content. Denial/scope change clears immediately; invalidated review remains invalidated. EN/AR320/360/390/tablet/desktop/200%zoom and keyboard test.
4. **P1 bootstrap/waterfall reduction (1–3d per contract).** Measure cold Calendar and selected detail refresh; implement minimal branch-local anchor/context or combined projection only where necessary. Parallelize independent reads. Acceptance: request budget before/after, same scope/bytes/permission/totals, signed receipts unchanged.
5. **P1 database work (2–5d plus representative workload).** Local skewed fixture/plan baseline; shared current context and eligible aggregates within one request; avoid JSON50→5 Home work. Conditional indexes only with selectivity/write/WAL evidence. Acceptance: equivalent authorized results/totals with lower measured rows/work; no stale-authority global cache.
6. **P2 cache pilot and cross-app adoption (2–4d pilot,3–6d adoption).** Choose coordinator alone versus one query library based on evidence; decide proposed stale allowances. Reject harmful public cache/private persistence. Test multiple users/tenants/roles/links and release key invalidation.
7. **P2 offline proposal (separate estimation after policy).** Public static assets may precede private capabilities; no offline operating queue in this remediation. Private support is a distinct product/privacy/recovery project, not a small CSS or cache switch.

Efforts are rough focused engineer time, not delivery promises; dependencies include design review where flow changes, security/privacy decisions, actual performance testing and existing staging release gates. Do not bundle a full layout/auth rewrite unless mount/timing evidence proves it is needed. Code rollback preserves server operation identities and treats presentation-cache versions as disposable; no irreversible schema/record change expected in initial batches. Each API/query contract change gets a version-compatible rollout/rollback plan. Never weaken tests to match faster behavior.

## Definition of Done for every affected journey

- Stable journey/action/screen/AO/AT/loading/security joins and current source recorded. PYSA reference patterns/defects disclosed; no copied authority assumptions.
- Every fetch has one projection owner, scope key, purpose, bounds, dependencies, fresh/initial/resume rules and cancellation handling. Distinguish duplicate suppression from obsolete response suppression.
- Declare exact request budgets from the contract. Existing examples: dated bootstrap2 independent calls;40-date program validation5 sequential calls; QR resolve/capture2intentional calls. New budgets measured rather than one universal “one call per screen.”
- Lists/relationships/histories have stable cursor limits and minimal columns; incomplete page not labelled complete. Counts are authoritative; inspect candidate work as well as payload size. Per-row SQL helpers reviewed at representative density.
- Native internal navigation avoids unnecessary documents; real Next routing tested in addition to component adapters. Back/Forward, task selection, scroll/focus and native tab return verified EN/AR.
- No duplicated same-key in-flight fetch; coordinated resume tested same-task and40ms-separated. Related mutations invalidate only the appropriate authorized projections. Tests distinguish initial load/revalidation/error/denial.
- Dirty text, stale previews, pending/unknown writes and durable original-operation recovery tested through disconnect/remount. Never retry a consequential write under a new identity automatically.
- Cache/persistence/offline capability explicitly declared per entity. No private cross-user cache; scope changes and denial tested. Unsupported offline actions say unavailable, never fake Saved.
- Meaningful two-academy, wrong-role, revoked link/member, expired invitation, stale version, duplicate/concurrent submission and interrupted-operation cases preserved wherever affected.
- Record cold/warm first useful p75≤3s, local feedback p75≤200ms, ordinary read p95<800ms, CLS≤0.1 on declared dataset/device/network/sample count; targets stay open until measured. Do not infer from mocked tests or cumulative SQL means.
- Track API starts/completions/aborts, payload bytes, DB work and normalized limiter/provider usage per task. No tokens/private payloads in evidence. No new logging/monitoring enabled without review.
- Refresh real-component factual captures only after UI/routes/wording change; docs-only joins may rebuild HTML from unchanged capture pack. Run review freshness/test and canonical documentation validators.
- Report design approved / implemented / locally tested / deployed / hosted verified / Owner accepted / independent security separately. No percentage or green suite substitutes for evidence.

## Anti-patterns to reject at review

Confirmed from NR01–17: defaulting all guarded links to location.assign; clearing the whole task for ordinary revalidation; separate focus+visible reloads; assuming microtask coalescing covers separated OS events; counting browser aborts as database savings; obtaining full Home just to know Calendar today; repeating selected-detail/list waterfalls without dependency review; mapping RSC prefetch1:1 to SQL; assuming one Redis evaluation equals one command; treating response bounds as query-work bounds; adding/removing indexes from tiny-table advisor hints; keeping uncertain operation identity only in component state for crash-supported paths; installing query libraries with default focus/retry settings; persisting private payloads simply to feel fast; replacing authoritative counts with loaded-page totals; treating every current permission read as waste.

## Regression monitoring and evidence

Use existing provider dashboards and scoped sanitized local diagnostics first. [Service impact](../04-engineering/request-service-impact.md) defines currently observed meters and G01–G09 owners. A future implementation may add sampled bounded metrics only after privacy/retention review; existing Sentry tracing/replay remains disabled. No email/child name/subject ID/raw URL/token/private reason in metric dimensions. Alert on changes per completed journey compared with same release/data/device profile, not arbitrary raw monthly growth. Expensive provider usage collection must be asynchronous/cached separately from every visitor. Failed telemetry is not zero cost or outage proof.
