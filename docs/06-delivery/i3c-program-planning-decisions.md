## Recommended outcome

Programs → open saved ready program → **Plan the program** → select the whole saved period or a smaller explicit date/weekday subset → set capacity, optional eligible same-branch Trainer and existing fictional players → inspect exact dated changes → apply reviewed work → reopen results. **Plan this date** remains available from each dated row and uses the existing atomic I3b journey. A whole-period action does not impose a28-day program limit; bounded preview/preparation pages are engineering controls; they must not become partial live commits.

## Revised direction for connected design

| Choice | Recommended behavior | Why / alternative |
|---|---|---|
| Authority and effects | Current active Academy Owner, existing academy/initial branch and ready private draft program only. Fictional staging data. Existing Trainer eligibility, positive capacity, duplicate and same-academy UTC overlap rules apply on every date. | No new Manager/Trainer/family visibility, appointment grant, notification, fee, attendance, time/recurrence edit or publication. |
| Selection | Whole saved period by default, explicit optional smaller range and weekday selection. Preview lists every targeted date; full scope is frozen by exact saved-date identities and versions. | A selected day is a date, not a newly generated recurrence. New/changed dates after review require a new review; no hidden inclusion. |
| Routine plan | One capacity/optional Trainer/fictional roster for selected unplanned dates, with optional weekday-specific choices. Weekday settings are resolved to exact dates before confirmation. | Default same values avoid repetitive work. A weekday-specific row must not silently inherit later changes to another row. |
| Existing date plans | Preserve every existing dated plan by default, show it as **Preserved individual plan**, exclude it from writes and show its current summary. | No automatic merging/replacement/removal of existing rosters. To change it, open **Plan this date** and review explicitly. Whole-program replacement of already planned dates is deferred rather than hidden behind a broad overwrite checkbox. |
| Snapshot semantics | Apply a reviewed snapshot to selected currently unplanned dates; there is no live inherited default. Later individual edits affect only that date. | Changing a program proposal does not silently change dates already saved, including prior program-apply results. Future reapply/propagation needs an explicit affected-date/replacement contract. |
| Conflicts | Review shows ready, preserved and blocked dates. Any blocked included date prevents the entire reviewed change from saving. Owner corrects choices or explicitly changes scope and reviews again. | No automatic ready-subset apply, skipped conflicts, dropped people or overbooking. Excluding dates is a deliberate new scope, never a retry shortcut. |
| Large operations | Bounded resumable private preparation followed by one authoritative all-or-none activation for the exact reviewed change set. Nothing prepared becomes a saved/effective dated plan before activation. | Implementation feasibility, lock duration and scale must be proved. Do not promise arbitrary scale, add an unapproved period cap, or silently revert to partial live saves. |
| Resume and retry | Reopen original preparation; show prepared versus unprepared, with zero live changes. Unknown final outcome uses **Check original operation**; it resolves to all committed or none. Revalidate current authority, eligibility, conflicts and every expected date version at activation. | Cancellation before activation prevents the entire change; cancellation racing activation resolves by serialization, not compensating per-date deletes. Already committed changes are not undone by cancel. Existing preserved plans remain unchanged. |

Example:40 dates,1 already individually planned,2 blocked by overlap → review37 ready,1 preserved,2 blocked. **Save is blocked; zero dates change.** Correct both conflicts to review39 changes+1 preserved, then save all39 together. If preparation stops at12/39, show12 prepared,0 saved; resume preparation. A final failure after any internal child write rolls back the whole activation. Unknown response reconciles all39 committed or0, never12 committed. If all targeted dates already have plans, offer inspection; no empty successful apply.

“All dates together” applies to every date in the exact reviewed write set. Existing plans excluded as preserved remain visible and unchanged; dates deliberately outside the scope are also unchanged. The connected preview must make those categories explicit before confirmation.
