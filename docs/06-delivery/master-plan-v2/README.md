## Authority and stable scope

1. Latest explicit Owner instructions and accepted AcademyOS decisions govern. This request authorizes the planning package and tooling; it does not approve unchosen fee formulas, identity/medical field collection, player-account ages, new permissions, offline commands or real-data launch.
2. Specific current domain/action/authority/recovery contracts govern implementation. Later scoped decisions supersede older proposals only for their stated scope. Keep the [decision history](../../00-governance/decisions-and-open-questions.md) and linked accepted packets.
3. The [Operations reference](../../03-design/operations-design-reference.md) governs presentation: **light default, Charcoal alternative**, compact resizable panes, coherent controls, useful density and complete workflows. The earlier dark-default and imported blue recommendations remain provenance.
4. PYSA is a read-only capability/workflow and defect reference. Its source UI, validation, action, database mapping and audit evidence are separate layers. They neither prove hosted behavior nor authorize copying its schema, private records or permission defects. Owner direction explicitly calls for simplifying or replacing unnecessary legacy work, especially finance. Retain useful business outcomes and accepted controls; justify fields, steps and reviews rather than chasing implementation parity.
5. Tools assist design and checking. A plugin suggestion, screenshot, generated rating or repository README cannot approve a business rule or establish working acceptance.

## What “complete” means

Track at least these independent dimensions for every delivered scope: **functional coverage; visual/workflow parity; multi-academy/multisport correctness; local/sync behavior; local tests; deployed exact source; hosted/installed/device evidence; Owner acceptance**. Independent external security review is deferred and nonblocking for authorized synthetic staging, never recorded as passed. Actual security/integrity defects remain engineering work. There is no honest overall percentage until a weighted, agreed scope and denominator exist.

A working minimal registration slice is not a complete Player module. A theme token is not redesign parity. An academy filter is not full tenant administration. A sport label or player `lane_group` is not a lane-allocation engine. A worker or installation icon is not whole-app offline support. A ready preview is not the live release. The [baseline](baseline-and-coverage.md) keeps these distinctions visible.
