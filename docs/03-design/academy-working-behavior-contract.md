## Target operating model and current boundary

First permitted use: establish scope → requested task essentials → bounded resumable dataset pages → transactional local coverage. Later use: unlock/verify compatible same-account local workspace under its accepted policy → query local records → small access/version check → synchronize changed or missing data quietly. Normal navigation must not restart a full directory/month download. A new/cleared/evicted store is a separate bootstrap event.

“All permitted directory pages” and a selected month prepared progressively are finite approved datasets, not an entire-database or unlimited whole-app preload. Complete on disk does not require all rows in memory. Code preparation, durable read replicas, transient query memory, drafts and original-operation identity have distinct owners. A durable local read does not grant a server command or automatically authorize offline edits.

Current source still uses no-store signed APIs and route-owned private results. Until the reviewed new model is implemented, document the current online-only/private-storage limits honestly. The earlier unaccepted WB-P01–WB-P04 summary-only/30second/5minute/intent-only proposals are **superseded**, not current pending choices or approval defaults. The v1 packet/storyboard remain historical evidence only.
