## Common action/state and security contract

Every studio view has deterministic loading, successfully empty, unavailable and restricted states. Restricted state clears private content and offers context review. Domain buttons perform local demonstration transitions only; UI predicates do not enforce product authorization. No fake success is used for blocked business rules: unresolved calculation/payment/activation/deletion remains explicit.

Inputs have labels; error summary receives focus; entered review fields persist in memory across failed operations/locale/theme where captured and are not private-storage policy. Confirmations are consumed by reviewed transitions. Leaving dirty input prompts. Source commitment and unknown effects are distinguishable; after committing, back/refresh does not imply undo. Local operation logs identify the simulation. Correction/refund/withdrawal are named distinct actions, not blanket undo.

Five dimensions for each domain: usability (person can explain scope, result and next step), speed (task-ready content before independent history), correctness (current identity/relationship/version and immutable source), cost (bounded projections and retries, no vendor fan-out/polling), recovery (original operation, explicit partial/stale/blocked outcomes). All remain review criteria, not measured results. Security/privacy is independent: tenant/field isolation, current capability, atomic/idempotent writes, private files/jobs/transport, redaction, containment and recovery need real layered evidence. Use canonical workflow acceptance cases and the separate final handoff/security matrix; model tests cannot close them.
