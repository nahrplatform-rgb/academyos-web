## Product direction

The compact-blue foundation is coherent enough to retain: a real workspace shell, native controls, legible blue primary actions and explicit review before consequential work. The next refinement should make it feel like one academy product rather than adjacent implementation slices. Put the current role, academy and branch near the task; let the content show what that person can do now. Keep diagnostics, blanket staging explanations and future-work notices secondary. Never turn the Guardian's minimal linked-player view or Trainer's minimal own-staff profile into an invented dashboard.

The source already refreshes after confirmed writes and on return to a page in several journeys. The recommendation is not to add indiscriminate auto-refresh. It is to make those triggers deliberate, preserve drafts and review intent, and stop presenting normal rereads and original-operation recovery as the same control. Read failure, failed delivery, unknown delivery and unknown commit must remain distinguishable.

## Role-by-role connected experience

**Platform Owner:** task-first admission directory; keep I1 semantic table and selected inspector on desktop, list → detail → Back on phone. Preserve loaded draft and row focus. Admission review names exact academy and intended Owner, with invitation state separate from delivery and membership. Revoke/reissue retain generation and original-operation handling; inspect does not invent audit history, totals, search or bulk actions. The prototype models the task hierarchy; it does not replace the implementation's directory mechanics.

**Invited Academy Owner:** invitation review names scope and intended verified recipient. Wrong account, unverified email, revoked/expired invitation and unknown acceptance have distinct next steps. Acceptance leads to workspace selection; “Open academy” resumes saved setup. Setup is a bounded initial-branch/sport task, with explicit review and clear links to implemented players and Trainer appointments. No fake calendar preview or inferred subscription is added.

**Academy Owner — people:** directory → draft → all scoped matching candidates → explicit different person or existing profile → review → confirmed record. Do not collapse matching candidates into a cosmetic warning or enable save before complete candidate review. Existing profile and new registration receipt must be visually distinguishable. Optional stored guardian contact stays labelled unverified and does not authorize appointment or email.

**Academy Owner — appointments:** enter exact separately authorized recipient, inspect only that intended recipient, review narrow scope, confirm invitation. Pending invitation, delivery, accepted access and ended access remain separate. Duplicate existing appointment is inspected rather than silently merged/reissued. Ending access names the exact link/Trainer appointment and reason; history and other roles survive. A pending invitation uses revocation wording; an accepted appointment uses end-access wording. No restore switch or broad staff administration is proposed.

**Guardian:** accept exact recipient invitation → linked player's name and branch only. With multiple authorized links, preserve current paginated link selection; no sibling inference, contact, payment, consent, media, messaging or attendance. On ending access, next read removes private details and explains how to choose another available workspace. Do not keep a cached private card behind an error.

**Trainer:** accept exact recipient invitation → own staff name, fixed Trainer role and initial branch only. No player roster, staff list, compensation or future dated session widget. After exact appointment ends, deny the next read and remove the profile; other roles remain independently selectable if authorized.

## Layout, localization and accessibility criteria

Keep baseline blue `#075bea`, ink `#172941`, native controls, compact desktop density and 6/8px radii. Use 44px phone controls/label targets, logical spacing, wrapped action groups and bounded line lengths. Reserve structural space while loading; do not preserve private values to prevent layout movement when authority is unknown. No red/yellow/green window buttons.

Use native headings, form labels and field semantics. Errors need plain text and live announcements, not color alone. Move focus on deliberate view changes to task heading, return to originating row/control after Back, and do not steal focus during background reads. Keep support references accessible in disclosure. Keyboard-only and screen-reader acceptance are distinct; prototype DOM checks do not certify assistive technology.

Translate task, state and action language together. Mirror layout with `dir=rtl`, use logical border/padding, isolate email/reference strings with `bdi` and LTR direction, preserve UTC label. Test Arabic long text, 320px/360px phone widths, desktop and 200% zoom; no forced single-line actions. Native validation and final Arabic copy still need Owner/device review.
